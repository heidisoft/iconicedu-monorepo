### 6) `[ASK USER]` Questions — Resolved

All seven questions below have been answered. Each is now tracked as a GitHub issue with a phased implementation plan, acceptance criteria, and a test plan; numbering is preserved from the original scan for traceability.

1. ~~Is the mixed Prisma/Supabase-client data-access pattern inside `apps/api` (§1, §3) an intentional split or unconverged migration debt?~~ **Resolved: migrate to Prisma** (phased; Supabase client stays for `.auth.*` calls only). Tracked in [#180](https://github.com/heidisoft/iconicedu-monorepo/issues/180).
2. ~~Is the inert global `ValidationPipe` a known gap, or is hand-rolled validation intentional?~~ **Resolved: `class-validator`-based DTOs are the intended approach** — convert all `@Body()` shapes repo-wide. Tracked in [#181](https://github.com/heidisoft/iconicedu-monorepo/issues/181).
3. ~~Is `@tanstack/react-query` in `apps/web` a planned-but-unstarted adoption, or unused?~~ **Resolved: leftover — remove.** Tracked in [#182](https://github.com/heidisoft/iconicedu-monorepo/issues/182).
4. ~~Are the empty `packages/shared-types/src/{domain,mappers,projections,validators}` directories active WIP or leftover scaffolding?~~ **Implemented:** each directory now documents its ownership. Shared message row and VM contracts remain in `packages/shared-types`, executable mapping helpers live in `packages/utils`, and message visibility remains an API-owned authorization rule. Tracked in [#183](https://github.com/heidisoft/iconicedu-monorepo/issues/183).
5. ~~Is the `email-provider.ts` no-op stub intentional, or a gap?~~ **Resolved: intentional** (email deprioritized) — make the skip visible via logging/metrics instead of silent. Tracked in [#184](https://github.com/heidisoft/iconicedu-monorepo/issues/184).
6. ~~Is `apps/api`'s configured-but-empty `test:e2e` tracked as planned work, or should it be removed?~~ **Resolved: not a near-term priority** — remove the dead script; revisit when e2e testing is prioritized. Tracked in [#185](https://github.com/heidisoft/iconicedu-monorepo/issues/185) (backlog).
7. ~~Is GitHub's native Dependabot enabled at the repo/org settings level?~~ **Resolved: not a near-term priority** — confirm/enable when prioritized. Tracked in [#186](https://github.com/heidisoft/iconicedu-monorepo/issues/186) (backlog).
