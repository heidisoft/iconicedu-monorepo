# Push Notification Copy Review

## Purpose

Review matrix for current push notification copy behavior across activity events.

## Source of Truth

- Dedicated push copy: `apps/api/src/lib/notifications/push-copy.ts`
- Activity inventory: `apps/api/src/lib/activity-feed/definitions/activity-definitions.ts`
- Job fallback behavior: `apps/api/src/lib/notifications/dispatch-jobs.ts`
- Final Expo body fallback: `apps/api/src/lib/notifications/providers/push-provider.ts`

## Notes

- `title` is the queued push title.
- `body` is the queued summary/body. If the queued body is empty, Expo may still use `rawEventPayload.content` or `rawEventPayload.preview`.
- "No dedicated push copy" means the event has no explicit case in `push-copy.ts` and falls back to the standard payload/title path.
- `class.session.rescheduled`, `class.session.canceled`, `session.reminder.sent`, and `session.feedback_request.sent` have dedicated class-session copy aligned with the activity feed variants.
- `session.completed` has dedicated push copy in `push-copy.ts`, but it does not appear in the current activity definition inventory.
- The personalized copy builder has explicit cases for class-session events and `payment.reminder.sent`; all other event types fall back to `payload.title` / `payload.summary`.
